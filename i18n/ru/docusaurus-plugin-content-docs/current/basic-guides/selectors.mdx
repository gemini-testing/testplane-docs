# Селекторы

Testplane предоставляет множество способов для поиска элементов на странице браузера.

## Рекомендации по использованию селекторов

Мы рекомендуем искать элементы так же, как это делают пользователи тестируемого приложения.

При выборе можно руководствоваться 3 факторами:

-   Ориентация на пользователя — селектор отражает то, что видит и использует пользователь
-   Стабильность — селектор не ломается при рефакторинге, изменениях CSS или структуры страницы
-   Уникальность — селектор однозначно идентифицирует нужный элемент

| Селектор / Способ выбора                                                    | Рекомендация | Примечания                                                                                                                                                                  |
| --------------------------------------------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| По видимому содержимому — тексту, роли, ... (`getByRole`, `getByText`, ...) | ✅ Лучший    | Ищем элементы так же, как это делают пользователи: по тексту, роли, label — стабильный и "честный" способ поиска.                                                           |
| По атрибуту `data-testid` (например, `[data-testid="submit"]`)              | ✅ Хорошо    | Атрибут `data-testid` создан специально для автоматизации: не влияет на стили/доступность, стабилен, явно обозначает цель элемента, но требует ручной разметки такими ID.   |
| По ID (например, `#main`)                                                   | ⚠️ Редко     | ID стабильнее классов, но все равно может зависеть от JS‑логики или изменений в разметке. Используйте, только если ID гарантированно устойчив.                              |
| По типу атрибута (например, `input[type="text"]`)                           | ⚠️ Редко     | Работает, если тип атрибута семантически значим и стабилен. Но может быть слишком общим (много элементов одного типа).                                                      |
| По атрибутам (кроме `data-testid`, например, `[name="email"]`)              | ⚠️ Редко     | Зависит от семантики HTML‑атрибутов. Может быть нестабильным (атрибуты меняют значение или удаляются).                                                                      |
| XPath (например, `(//button)[2]`)                                           | 🔴 Плохо     | Позиция элемента может измениться, селекторы XPath как правило сложно поддерживать. Однако они могут быть полезны, так как дают максимум возможностей для поиска элементов. |
| По классу (например, `.sidebar .list-item.state-opened-qU1azF`)             | 🔴 Плохо     | Не связан с поведением пользователя и не отражает семантику, жесткая завязка на иерархию.                                                                                   |

## WebdriverIO

В Testplane поддерживается поиск элементов, совместимый с синтаксисом WebdriverIO: по CSS селекторам, по XPath, по тексту элементов и по другим признакам, которые описаны ниже.

В примерах ниже тест начинается на странице документации с меню, кнопкой `Get started` и диалогом поиска.

### Селекторы по тексту

Данный вид селекторов позволяет искать элементы по содержащемуся в них тексту:

-   `=text` — точный поиск текста
-   `*=text` — поиск по частичному совпадению текста
-   `a*=text` — поиск по тексту внутри тега `<a>`
-   `div.=text` — case-insensitive поиск текста внутри тега `<div>`

```javascript testplane=selectors-link-text fixture=selectors-guide
const assert = require("node:assert/strict");

const nav = await browser.$("nav");
const exact = await nav.$("=Documentation");
assert.equal(await exact.getAttribute("href"), "#docs");
assert.equal(await nav.$("*=Docum").getText(), "Documentation");
assert.equal(await nav.$("a*=Document").getText(), "Documentation");
assert.equal(await browser.$("div.=testplane").getText(), "Testplane");
```

Стоит использовать, если:

-   текст элементов стабилен
-   вам необходимо, чтобы тест был максимально приближен к реальным пользовательским сценариям

### CSS-селекторы

#### По атрибуту data-testid

Данный способ подходит для поиска элементов, которые размечены атрибутами для тестирования.

```javascript testplane=selectors-css-test-id fixture=selectors-guide
const assert = require("node:assert/strict");

const main = await browser.$('[data-testid="main-content"]');
assert.equal(await main.$("h1").getText(), "Documentation guide");
```

Стоит использовать, если:

-   создаете селекторы специально для тестирования
-   нужна стабильность селекторов независимо от изменений UI/стилей

#### По классу

Чтобы найти элемент на странице по классу, используйте селектор `".class-name"`.

```javascript testplane=selectors-css-class fixture=selectors-guide
const assert = require("node:assert/strict");

const navbar = await browser.$(".navbar");
assert.equal(await navbar.isDisplayed(), true);
assert.equal(await navbar.$("a").getText(), "Documentation");
```

Стоит использовать, если:

-   класс является стабильным и не генерируется динамически
-   нужен быстрый и простой способ найти элемент
-   класс семантически описывает элемент (например, `.error-message`, `.success-banner`)
-   вы работаете с компонентными библиотеками, где классы являются частью API

#### По id

Чтобы найти элемент по `id` используйте селектор вида `"#id"`.

```javascript testplane=selectors-css-id fixture=selectors-guide
const assert = require("node:assert/strict");

const main = await browser.$("#main");
assert.equal(await main.getTagName(), "main");
assert.equal(await main.isDisplayed(), true);
```

Стоит использовать, если:

-   вам необходим быстрый и простой способ поиска элементов
-   `id` является частью публичного API компонента
-   нужна максимальная производительность селектора (`id` — самый быстрый селектор)

#### По типу атрибута

Для поиска элемента по атрибуту используйте селектор вида `input[type="name"]`.

```javascript testplane=selectors-css-type fixture=selectors-guide
const assert = require("node:assert/strict");

const buttons = await browser.$$('button[type="button"]');
assert.equal(buttons.length, 2);
assert.equal(await buttons[0].getText(), "Get started");
```

Стоит использовать, если:

-   нужно найти все элементы определенного типа (все чекбоксы, все радиокнопки)
-   нужно работать с семантическими HTML5 типами (`email`, `tel`, `url`, `date`)

### XPath-селекторы

#### По тексту элемента

Чтобы найти элемент по содержащемуся в нем тексту, используйте селектор `//element[text()="text"]`.

```javascript testplane=selectors-xpath-text fixture=selectors-guide
const assert = require("node:assert/strict");

const link = await browser.$('//a[text()="Docs"]');
assert.equal(await link.getAttribute("href"), "#guides");
```

Стоит использовать, если:

-   текст элемента уникален и стабилен (названия кнопок, заголовки)
-   другие стратегии поиска элементов оказались неприменимы

#### По атрибутам

Для поиска элемента по атрибуту используйте селектор вида `//element[@type="atribute"]`.

```javascript testplane=selectors-xpath-attribute fixture=selectors-guide
const assert = require("node:assert/strict");

const button = await browser.$('//button[@type="button"]');
assert.equal(await button.getText(), "Get started");
```

Стоит использовать, если:

-   нужны сложные условия поиска (комбинации атрибутов)
-   работаете с динамическими атрибутами (`data`-атрибуты с переменными значениями)
-   нужна гибкость в поиске (частичные совпадения, начало/конец строки)
-   CSS-селекторы не могут выразить нужную логику
-   нужно найти элемент по отсутствию атрибута

#### Навигация по DOM

Используя XPath, вы можете навигировать по DOM-дереву.

Начнём с поля электронной почты и найдём его родителя и форму-предка:

```javascript testplane=selectors-xpath-ancestors fixture=selectors-tree
const assert = require("node:assert/strict");

const field = await browser.$("//input[@name='email']/..");
assert.equal(await field.getAttribute("id"), "email-field");
const form = await browser.$("//input[@name='email']/ancestor::form[@id='registration']");
assert.equal(await form.getTagName(), "form");
```

Для поиска сообщения об ошибке и подписи поля используем соседние элементы:

```javascript testplane=selectors-xpath-siblings fixture=selectors-tree
const assert = require("node:assert/strict");

const error = await browser.$(
    "//input[@class='invalid']/following-sibling::span[@class='error'][1]",
);
assert.equal(await error.getText(), "Enter an email address");
const label = await browser.$("//input[@name='password']/preceding-sibling::label[1]");
assert.equal(await label.getText(), "Password");
```

Двойная косая черта выбирает всех потомков, одинарная — только прямых детей. Можно также подняться к родителю и выбрать следующий раздел:

```javascript testplane=selectors-xpath-descendants fixture=selectors-tree
const assert = require("node:assert/strict");

const fields = await browser.$$("//form[@id='checkout']//input");
assert.equal(fields.length, 2);
assert.equal(await fields[1].getAttribute("name"), "street");
const topLevel = await browser.$$("//ul[@class='menu']/li");
assert.equal(topLevel.length, 2);

const next = await browser.$("//h2[text()='Contacts']/../following-sibling::section[1]");
assert.equal(await next.getAttribute("id"), "billing");
```

Подобный вид навигации по дереву не рекомендуется использовать из-за своей хрупкости, но он возможен.

#### XPath: индексы и позиции

XPath позволяет выбирать элементы по их позиции в наборе результатов.

```javascript testplane=selectors-xpath-position fixture=selectors-guide
const assert = require("node:assert/strict");

const thirdLink = await browser.$("(//nav//a)[3]");
assert.equal(await thirdLink.getText(), "API");
```

Стоит использовать, если:

-   нужен доступ к элементу по его позиции в наборе результатов
-   тестируете пагинацию или списки с определенным порядком
-   работаете с таблицами, и нужна конкретная строка
-   нужен первый или последний элемент среди нескольких одинаковых
-   тестируете сортировку (проверка, что элемент на правильной позиции)

### Shadow-DOM-селекторы

Shadow-DOM-селекторы позволяют работать с элементами внутри Shadow DOM — инкапсулированной части DOM-дерева. Например, если у вас есть кастомный элемент `my-custom-element`, вы можете найти кнопку внутри его Shadow DOM с помощью `shadow$("button")`.

```javascript testplane=selectors-shadow fixture=selectors-guide
const assert = require("node:assert/strict");

const widget = await browser.$("my-custom-element");
const button = await widget.shadow$("button");
await button.click();
assert.equal(await button.getText(), "Expanded");

const items = await widget.shadow$$(".slot-item");
assert.deepEqual(await items.map(item => item.getText()), ["One", "Two"]);
```

Стоит использовать, если:

-   работаете с Web Components и Custom Elements
-   приложение использует Shadow DOM для инкапсуляции стилей
-   тестируете компоненты из сторонних библиотек (Lit, Stencil, native Web Components)
-   нужен доступ к элементам внутри shadow root
-   работаете с дизайн-системой на базе Web Components

## Testing Library

Testing Library позволяет искать элементы так, как их ищут на странице пользователи — по тексту, типу элемента или другим атрибутам, которые не зависят от деталей вашей верстки.

Чтобы использовать данный вид селекторов, необходимо [установить Testing Library](../../guides/how-to-add-testing-library).

### ByRole

`getByRole` — основной метод в Testing Library, который позволяет находить элементы по их ARIA-ролям. Например, если вы используете метод `browser.getByRole("button", { name: /submit/i })`, то найдете кнопку с текстом, содержащим `submit`.

```javascript testplane=selectors-by-role fixture=selectors-library
const assert = require("node:assert/strict");

const start = await browser.getByRole("button", { name: "Get started" });
await start.click();
assert.equal(new URL(await browser.getUrl()).hash, "#docs");
```

### ByLabelText

Для поиска элементов форм по тексту их меток (`label`) используйте метод `getByLabelText`.

```javascript testplane=selectors-by-label-text fixture=selectors-library
const assert = require("node:assert/strict");

const openSearch = await browser.getByLabelText(/open search/i);
await openSearch.click();
assert.equal(await browser.$("dialog[open]").isDisplayed(), true);
```

### ByPlaceholderText

Чтобы найти поле ввода по тексту `placeholder`, используйте селектор `getByPlaceholderText`.

```javascript testplane=selectors-by-placeholder-text fixture=selectors-library
const assert = require("node:assert/strict");

const openSearch = await browser.getByLabelText("Open search");
await openSearch.click();

const input = await browser.getByPlaceholderText("Search docs");
assert.equal(await input.isDisplayed(), true);
```

### ByText

Чтобы найти текстовый элемент по его содержимому, используйте метод `getByText`.

```javascript testplane=selectors-by-text fixture=selectors-library
const assert = require("node:assert/strict");

const start = await browser.getByText("Get started");
assert.equal(await start.isClickable(), true);
await start.click();
assert.equal(new URL(await browser.getUrl()).hash, "#docs");
```

### ByDisplayValue

Для поиска элемента по их текущему значению используйте метод `getByDisplayValue`.

```javascript testplane=selectors-by-display-value fixture=selectors-library
const assert = require("node:assert/strict");

const openSearch = await browser.getByLabelText("Open search");
await openSearch.click();
const input = await browser.$('input[type="search"]');
await input.setValue("html-reporter");

const match = await browser.getByDisplayValue("html-reporter");
assert.equal(await match.isEqual(input), true);
```

### ByAltText

Для поиска изображения по тексту `alt` используйте метод `getByAltText`.

```javascript testplane=selectors-by-alt-text fixture=selectors-library
const assert = require("node:assert/strict");

const cover = await browser.getByAltText("The Great Gatsby");
assert.equal(await cover.getTagName(), "img");
assert.ok((await cover.getProperty("naturalWidth")) > 0);
```

### ByTitle

Чтобы найти элемент по атрибуту title, используйте метод `getByTitle`.

```javascript testplane=selectors-by-title fixture=selectors-library
const assert = require("node:assert/strict");

const link = await browser.getByTitle("Direct link to Rich Debugging Capabilities");
assert.equal(await link.getAttribute("href"), "#debugging");
```

### ByTestId

`getByTestId` используется как последний вариант, когда другие методы не подходят. Например, если вы используете `browser.getByTestId("submit-button")`, то найдите элемент с атрибутом `data-testid="submit-button"`

```javascript testplane=selectors-by-test-id fixture=selectors-library
const assert = require("node:assert/strict");

const openSearch = await browser.getByLabelText("Open search");
await openSearch.click();

const input = await browser.getByTestId("search-input");
await input.setValue("selectors");
assert.equal(await browser.$("output").getText(), "selectors");
```
