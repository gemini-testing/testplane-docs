# respond

## Обзор {/* #overview */}

Используйте команду `respond`, чтобы всегда отвечать одной и той же перезаписью.

<Admonition type="info">
    Читайте также рецепт «[Как отслеживать и перехватывать сетевые запросы и
    ответы][how-to-intercept-requests-and-responses]».
</Admonition>

## Использование {/* #usage */}

```javascript
mock.respond(overwrites, { headers, statusCode, fetchResponse });
```

## Примеры использования {/* #examples */}

В примере используется WebDriver BiDi: кнопка `#reload` отправляет GET на `/api/items`, а `#source` показывает результат.

```javascript testplane=mock-respond fixture=matchers-network
const mock = await browser.mock("/api/items", { method: "GET" });
mock.respond({ source: "saved list" }, { statusCode: 200 });

for (let i = 0; i < 2; i++) {
    await browser.$("#reload").click();
    await expect(browser.$("#source")).toHaveText("saved list");
}
```

В сессии CDP можно вычислить тело ответа из данных запроса. В примере кнопка `#save` отправляет JSON с полем `title`. Транспорт WebDriver BiDi не поддерживает функцию вместо тела ответа.

```javascript testplane=mock-respond-dynamic fixture=matchers-network transport=cdp
const mock = await browser.mock("**/api/items", { method: "POST" });
mock.respond(request => ({ source: JSON.parse(request.postData).title }), {
    statusCode: 201,
    headers: { "Content-Type": "application/json" },
    fetchResponse: false,
});

await browser.$("#save").click();
await expect(browser.$("#source")).toHaveText("Ship feature");
```
