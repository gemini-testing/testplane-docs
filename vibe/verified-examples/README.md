# Проверенные примеры команд Testplane

Проект получен из отдельного проекта, созданного командой `npm init testplane@latest`. Он сохраняет исполняемые примеры для 28 новых команд и связанных исправлений существующих страниц в обеих локалях. Проверяются 86 блоков кода на 82 страницах по 41 тестовому файлу; два файла содержат по два теста. `manifest.json` связывает страницу EN, страницу RU и тест. Скрипт `verify-snippets.cjs` проверяет точное совпадение блоков JavaScript с тестовыми файлами.

## Окружение

-   Node.js 22.21.1.
-   Testplane 9.3.2 и `@testplane/webdriverio` 9.6.2; полный граф зависимостей закреплен в `package-lock.json`.
-   Chrome for Testing 150.0.7871.124, WebDriver BiDi.
-   Для `downloadFile`: Selenium Grid 4.50.0 с управляемыми загрузками и `se:downloadsEnabled: true`.
-   Исходный изолированный проект: `/private/tmp/testplane-docs-examples-20261009`.

## Запуск

Из этого каталога установите зависимости через `npm ci --legacy-peer-deps`. Флаг нужен для воспроизведения сохраненного lock-файла: в нем `@puppeteer/browsers@3.0.4` требует peer-зависимость `proxy-agent >=8.0.1`, а закреплена версия `6.5.0`. Без флага `npm ci` в npm 10.9.4 отклоняет этот граф. Зависимости и lock-файл при повторной проверке не обновлялись. `npm test` поднимает HTTP-стенд на свободном порту localhost, запускает браузерные тесты и закрывает HTTP-сервер после завершения. Сервер отдает только синтетические тестовые данные. Для получения Chrome и драйвера при первом запуске может понадобиться сеть.

`npm run check:snippets` проверяет соответствие тестов страницам; запускайте эту команду из сохраненного в репозитории каталога, а не из отдельной копии проекта.

`npm run test:selenium` запускает отдельный тест скачивания. Этот стенд рассчитан на **локальный Grid на той же машине**: HTTP-сервер слушает только `127.0.0.1`, и этот адрес передается браузеру в `baseUrl`. Grid по умолчанию ожидается на `http://127.0.0.1:4446`; другой локальный адрес или порт можно передать через `SELENIUM_GRID_URL`. Переменная `EXAMPLE_CHROME_BINARY` позволяет указать путь к браузеру на локальном узле Grid. Простая замена адреса на внешний Grid не сработает: удаленный браузер не видит локальный HTTP-стенд. Для удаленного запуска сначала нужен отдельно настроенный туннель, делающий этот loopback-адрес доступным в браузерной среде; такой запуск здесь не проверялся. Включите управляемые загрузки по [инструкции Selenium](https://www.selenium.dev/documentation/webdriver/remote_webdriver/#enable-downloads-in-the-grid).

## Изоляция и найденные ограничения

-   `retry: 0`: итоговый успех не скрывает автоматические повторы.
-   `testsPerSession: 1`: каждый тест использует новую браузерную сессию.
-   `isolation: false` и одна вкладка нужны для проверенных примеров `throttleCPU` и `throttleNetwork`: реализация обращается к первой странице Puppeteer.
-   В проверенной связке `throttleNetwork("online")` не восстанавливает сеть после `"offline"`. Пример завершает офлайн-сессию и проверяет доступность сети в следующей.
-   В WDIO 9.6.2 флаг автоматической сетевой подписки общий для модуля. Примеры моков явно вызывают `sessionSubscribe`, чтобы получать события после создания новой сессии тем же воркером.
-   `url` с `wait: "networkIdle"` в проверенной версии падает при поиске запроса навигации по context ID. Опубликованный пример использует `complete`; неуспешная диагностика сохранена отдельно.
-   Мобильные команды отложены пользователем: рабочая Appium-среда пока не предоставлена. Эти примеры и страницы не добавлялись.

## Результаты

Финальные результаты и контрольные суммы примеров сохраняются в `evidence/results.json`. Логи этапов и окончательного прогона лежат рядом. Успех сборки MDX не считается доказательством выполнения примеров: в отчетах эти проверки разделены.

Этапы 1–4 и немобильная часть этапа 6 выполнены. Итоговая проверка немобильного объема (этап 7) выполнена: 42/42 Chrome/BiDi и 1/1 Selenium, retries 0; линтер, типы, EN/RU build и сверка примеров проходят. 2026-10-14 исправлены оба оставшихся уточнения текста (`setViewport` и область действия `addInitScript`) в EN/RU; результаты повторной проверки сохраняются в `evidence/review-fixes-20261014/`. Подробнее — `evidence/review.md`. Этап 5 и мобильные ссылки этапа 6 отложены пользователем: 11 мобильных команд не добавлены и не проверены. Публикация требует отдельного согласования.

В гайде эмуляции проверены три измененных JavaScript-блока (сеть и CPU). Остальные, не измененные этой задачей примеры гайдов не входят в отчет о runtime-проверке.
